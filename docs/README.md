Start here for the ideas that cut across every page:

- **Environment variables are defaults; the settings store is the authority.** Everything the
  product reads from configuration is editable in it, persists to `DATA_DIR/settings.json`, and
  takes effect on the next request without a restart. The mechanism is in
  [Architecture](architecture/architecture.md#the-runtime-container-and-why-no-restart-is-true),
  the write path in [Data flow](architecture/data-flow.md), the developer view in
  [Extension points](developer/extension-points.md#the-settings-model-environment-defaults-store-authority),
  the partner view in [White-labelling](developer/white-label.md#the-settings-model), and the
  operator view in the [Admin walkthrough](business/walkthrough-admin.md).
- **The API is browsable inside the product** at `/api`, generated from the deployment's own
  OpenAPI document. [`developer/api-reference.md`](developer/api-reference.md) is the same contract
  in prose, generated by `make docs` — never hand-edited.
- **`DATA_DIR` now holds configuration, not just job history**, which changes the backup and
  multi-machine story: [Deployment topologies](architecture/deployment-topologies.md) and
  [Scaling](architecture/scaling.md).
