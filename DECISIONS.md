# DECISIONS.md — Call Analysis product decisions

Workspace-level decisions (D-01…D-18) live in the parent `DECISIONS.md`. This file records the
choices made inside this product. Format: `D-CA-nn · date · decision · why · consequences`.

| # | Date | Decision | Why | Consequences |
|---|---|---|---|---|
| D-CA-01 | 2026-09-12 | **Next.js App Router owns routing; the platform `App` router is not mounted.** `lib/api.ts` is a thin adapter that gives every `app/api/v1/**/route.ts` handler the platform's pipeline: request id, auth, per-IP token bucket, OpenAPI validation, problem+json, security headers, access log and usage counters. Session cookies are signed by a real platform `App` instance so the HMAC format matches every other ARAG product; `authenticate` and the rate limiter are ported (≈60 lines) because they need `IncomingMessage`. | Two routers in one process cannot both own `/api/v1`, and Next's file-based routing is the reason the framework was kept (D-04). | One small adapter to keep in step with the platform; `test/unit/api-adapter.test.ts` pins the ported logic, and the contract tests assert spec/implementation parity in both directions. |
| D-CA-02 | 2026-09-12 | **Route coverage is asserted from `API_ROUTES` plus a filesystem walk of `app/api/v1`,** not from `missingFromSpec(app, doc)`. | That helper needs a platform `App` instance, which this product does not build. | `test/contract/openapi.test.ts` fails if a handler is added without a spec entry, if a spec entry has no handler, or if `API_ROUTES` drifts from either. |
| D-CA-03 | 2026-09-12 | **`ARAG_BASE` is renamed `ARAG_BASE_URL`, with the old name read as a fallback.** | The platform standardises on `ARAG_BASE_URL`; the deployed Fly app and existing `.env.local` files still set `ARAG_BASE`. | `applyLegacyEnvAliases()` maps it at boot; documented in `.env.example` and covered by a test. The alias can be dropped once the Fly secret is renamed. |
| D-CA-04 | 2026-09-12 | **Reads are cached in-process (catalog ids, per-call summaries and details, labelsets, dashboard) with a 60 s TTL, single-flight loading and explicit invalidation on upload/delete/provision.** | The audit measured ~600 ARAG requests per dashboard view at 200 calls; rails multiplied it. A TTL cache with de-duplicated loads collapses that to one fetch per call per window. | Freshly uploaded calls can be up to `CALLS_CACHE_TTL_MS` stale in aggregates; uploads and deletes invalidate immediately, and the admin panel can clear the cache. Multi-machine deployments cache per machine — documented in `docs/architecture/scaling.md`. |
| D-CA-05 | 2026-09-12 | **`POST /api/v1/calls` creates the resource synchronously and returns `202` with a job that waits for transcription.** | The caller needs the call id and a `Location` immediately; only transcription and retrievability are slow. Keeping the recording bytes out of the persisted job input also keeps `DATA_DIR` small. | The job's input is `{callId, title, transcribed}`; the upload itself is bounded by `MAX_BODY_BYTES` and a MIME allowlist. |
| D-CA-06 | 2026-09-12 | **The taxonomy (`lib/domain/taxonomy.ts`) and the 24 demo scenarios (`lib/domain/scenarios.ts`) moved out of `scripts/` into the product,** and the scripts became thin HTTP clients of `/api/v1`. | The labelsets and agents are product behaviour — the admin panel provisions them and the mock seeds from them. Scripts that reimplement ingestion drift from the API. | `scripts/*.ts` need a running server and hold no ARAG credentials of their own; `scripts/reset.ts` additionally refuses a live Knowledge Box without `CALLS_ALLOW_DESTRUCTIVE=1`. |
| D-CA-07 | 2026-09-12 | **macOS `say` + `ffmpeg` media rendering is optional.** `scripts/gen-media.ts` writes a transcript-only manifest when they are unavailable. | The product must be buildable and demoable on Linux and in CI; rendered audio is a nicety for the live demo only. | Documented in `docs/developer/local-dev.md`; the mock ARAG synthesises timestamped transcripts either way. |
| D-CA-08 | 2026-09-12 | **`ARAG_MOCK=1` seeds the mock Knowledge Box with real transcripts and then runs the product's own labeler and ask agents against it at boot.** | A demo mode that shows empty charts is not a demo. Running the real taxonomy against the mock proves the agent definitions as well as the UI. | First request after boot pays the seeding cost (~1 s for 13 calls); `CALLS_MOCK_SEED` tunes the corpus size. |
| D-CA-09 | 2026-09-12 | **The REMi answer-quality call stays best-effort and time-capped, and is skipped entirely for a declined answer.** | `/predict/remi` can fail or be slow, and it scores topical relevance rather than whether an answer was given — it rated a refusal as high confidence in the live 3 Sep audit. | The badge falls back to the citation-coverage floor; a decline shows no badge at all. |
| D-CA-10 | 2026-09-12 | **Generated metric values are validated against the taxonomy enums before they reach a chart** (`sanitizeMetrics`). | A model can return prose where an enum was requested; "Not enough data to answer this." once rendered as a line-of-business category. | Invalid values are dropped, not displayed; the dashboard reports `withMetrics` so the gap is visible. |
| D-CA-11 | 2026-09-12 | **`lib/version.ts` holds the product version instead of importing `package.json`.** | The OpenAPI module is imported by Node-run CLI scripts, which have no bundler to resolve a JSON import (and Node requires an import attribute). | A contract test asserts the constant matches `package.json`. |
